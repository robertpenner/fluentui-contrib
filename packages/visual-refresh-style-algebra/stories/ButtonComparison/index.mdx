## The question this page answers

When button styling is updated for Visual Refresh or adapted for Teams, **which differences are intentional, and which would indicate a regression?**

This page compares three familiar outcomes: the Fluent 2 baseline, Fluent Visual Refresh, and Teams Visual Refresh. It shows what each design direction deliberately changes, such as button height, while holding state, appearance, content, and direction steady.

## What decision this can inform

Use this comparison to decide whether an observed difference belongs to an agreed design direction or product requirement, or whether one implementation changed the result by accident. The page makes a difference reviewable; it does not decide which height or appearance a product should require.

## Read it in three passes

1. **Read the card title.** It names the design direction being shown: Fluent 2, Fluent Visual Refresh, or Teams Visual Refresh.
2. **Read the details line.** It records the conditions used for that button. Most conditions intentionally stay constant, making differences between cards easier to explain.
3. **Compare the two buttons inside the card.** They are produced by different implementations of the same styling rules and should look and behave the same. In this research, those implementations are called **Layered** and **Semantic**. You do not need to understand their internals to use this page.

## What working as intended looks like

- Within every card, the two buttons should be visually indistinguishable. Seeing the same button twice is intentional: it checks that changing the implementation does not change the user-facing result.
- The Fluent Visual Refresh reference should be 36 px tall. The Fluent 2 baseline and Teams Visual Refresh reference should remain 32 px tall.
- Differences between cards may be intentional design differences. A difference within a pair indicates an implementation mismatch or a rendering problem.
- The card labels and details should make every visible difference traceable to a stated design condition rather than an unexplained CSS override.

This page is deliberately narrow. Continue to the [Curated matrix](?path=/docs/packages-visual-refresh-style-algebra-curated-matrix--docs) to see whether the two implementations remain consistent when more conditions interact.
