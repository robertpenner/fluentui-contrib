## The question this page answers

How can product and visual-language policy change a button while two different resolver architectures still agree on the result?

This is the smallest technical comparison in the package. It holds interaction, appearance, content, and direction steady, then compares three reference policies. Every card describes one button case and renders its contract twice through the same clean-room renderer.

## Read it in three passes

1. **Read the card title.** It names the policy difference being isolated: Fluent 2, Fluent Visual Refresh, or Teams Visual Refresh.
2. **Read the dimension line.** This is the complete input case. Most dimensions intentionally stay constant so that differences between cards remain interpretable.
3. **Compare Layered with Semantic inside the card.** These labels name the route used to compute the contract. They do not name two desired visual variants.

## What working as intended looks like

- Within every card, the Layered and Semantic buttons should be visually indistinguishable. Agreement is the result under test, not accidental duplication.
- The Fluent Visual Refresh reference should be 36 px tall. The Fluent 2 baseline and Teams Visual Refresh reference should remain 32 px tall.
- Differences between cards may be intentional policy differences. Differences within a Layered/Semantic pair indicate resolver divergence or a renderer problem.
- The card labels and dimensions should make every visible difference traceable to an input or named policy, rather than to an unexplained CSS override.

This page is deliberately narrow. Continue to the [Curated matrix](?path=/docs/packages-visual-refresh-style-algebra-curated-matrix--docs) to see whether the same agreement survives more interacting dimensions.
