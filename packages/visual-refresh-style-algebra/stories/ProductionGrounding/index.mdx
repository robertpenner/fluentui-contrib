<Title>What the real Button path does with content and icons</Title>

The [CAP Button audit](?path=/docs/packages-visual-refresh-style-algebra-cap-button-audit--docs) identified content and icon placement as a small place to begin. This page opens that first slice: twelve combinations of icon presence, child content, and icon position, all run through public Fluent Button behavior and the Visual Refresh CAP style hook.

## What the audit runs

For each row, the check uses the installed component code rather than recreating its conditions:

1. public `ButtonProps` supply the icon, children, and `iconPosition` input;
2. Fluent's `useButton_unstable` normalizes that input;
3. Fluent's `renderButton_unstable` determines which slots render and in what order;
4. CAP's `useButtonStyles_unstable` selects the Visual Refresh style branch.

This is a component-level integration test running in the package's unit-test harness. It renders each Button with and without CAP styling, then records slot presence, rendered order, and relative class changes. Generated class names stay inside the comparison because their spelling is unstable; the page reports the four recurring effects they produce.

The test runs in a simulated DOM, so it establishes structure and style selection, not browser layout or pixel equivalence.

## How to read the final column

The first five columns report the production path. The final column asks whether the later research model can describe the result:

- **Direct match** means the model keeps the observed distinction.
- **Grouped with another input** means two production inputs reach the same modeled case; the row names what was set aside.
- **Outside the model** means the production path handled the input, but the model has no content case for it.

These labels do not mean product-supported or product-unsupported. No product contract was found for these twelve scenarios, so support remains unknown.

The second table tries real React child values. It shows where JavaScript truthiness, CAP's chosen style branch, and rendered content disagree, especially for an empty fragment.
